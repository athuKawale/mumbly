UI/UX Design System
Design that disappears
Mumbly's design philosophy: the interface should be invisible when you don't need it, and instantly present when you do. Every pixel earns its place. Every interaction reduces friction.

Onboarding Flow
A 4-step onboarding that explains the core value prop, requests permissions with clear explanations, and gets the user to their first capture in under 90 seconds. No account required to start.
4 Onboarding Screens
  • Screen 1 — Welcome: Brand moment. Animated glow bubble. Single CTA "Get started".
  • Screen 2 — How it works: 3-step animation: Tap bubble → speak → get digest. No walls of text.
  • Screen 3 — Permissions: Mic + overlay + notifications. Each with a clear human reason why. "We need mic to transcribe. Nothing is recorded unless you tap."
  • Screen 4 — Set digest time: Time picker for daily email. Pre-filled to 9 PM. Email input. User can skip.
Design Rules
  • Progress dots always visible — user knows where they are
  • Back navigation always available — no traps
  • Skip option on every screen after Screen 1
  • Single action per screen — no decision overload
  • Permission rationale on the screen BEFORE the OS dialog

Home
The command center. Shows the day's captures at a glance, upcoming alarms, digest countdown, and recent captures feed. The floating bubble is always visible here. No deep navigation required — everything important is surfaced.
Layout Structure (top to bottom)
  • Status bar area (28dp): Transparent, system time visible
  • Greeting + date (48dp): Personalized greeting + current date. Changes based on time of day.

  • Context cards (variable): Next alarm + Digest countdown. Smart — hidden if nothing relevant.
  • Captures feed (flex): Last 5 captures, scrollable. Color-coded dots by tag type.
  • Floating bubble: Always at bottom-right, above bottom nav. 56dp circle.
  • Bottom nav (56dp): Home / Todos / History / Settings. 4 items max.

Active State
Recording
This screen appears when the bubble is tapped. The entire interface shifts to coral — a strong visual signal that recording is active. The user can stop by tapping anywhere, the bubble, or the stop button. No confusion about state.
Visual State Changes
  • Idle bubble: Violet with microphone icon + slow pulse ring
  • Recording bubble: Coral, transitions to stop icon, ambient coral glow fills screen
  • Processing (after stop): Amber pulse + spinner. "Transcribing..." text. ~2 seconds.
  • Saved: Green flash + checkmark + "Saved" toast for 1.5s. Returns to previous state.
Accessibility
  • TalkBack announces "Recording started" and "Recording stopped"
  • Recording indicator in notification bar (Android requirement)
  • Tap anywhere on screen stops recording — large hit target
  • Timer so user knows how long they've been talking

Daily Digest
In-app preview of what will be emailed at the user's set time. Captures are clustered by AI into Work, Ideas, Personal, Health, Finance. Tabs for quick filtering. Each card is tappable to play source audio.
Cluster Logic
  • Gemini Nano classifies each capture into a category at transcription time
  • Categories: Work, Ideas, Personal, Health, Finance, Misc
  • Each cluster has a color dot that matches the capture feed on Home
  • Sorted by capture count descending — most active category first
  • Empty clusters are hidden (not shown as empty sections)
Card Interactions

  • Long press → quick actions: Add to todo / Set alarm / Share / Delete
  • Swipe right on card → mark as reviewed (grays out)

Todos & Alarms
Auto-extracted tasks from voice captures. Each todo links back to its source capture. Alarms set via voice appear here with their time. No manual input needed — but user can edit, add manually, or snooze.
Todo Card Anatomy
  • Circle checkbox: 20dp, tap to complete with satisfying scale animation
  • Task text: 14px DM Sans, max 2 lines before truncating
  • Source attribution: "From: capture name · time" in 11px muted text — links to audio
  • Alarm indicator: Amber ⏰ text if a reminder was detected or set
  • Swipe left: Delete with undo toast (3 seconds)
  • Swipe right: Mark complete
Sort & Filter
  • Default: Open tasks first, sorted by detected urgency (time-bound tasks float up)
  • Completed section collapses after 5 items with "Show all" expander
  • FAB for manual task add (+ button, bottom-right near bubble)

Settings
Clean, grouped settings with no visual noise. Toggles for privacy settings are prominent. The upgrade to Pro is surfaced naturally without being pushy — one row, never a popup.
Settings Groups
  • Digest: Send time (time picker), email address, format preferences
  • Capture: Language, clip length, auto-tagging on/off, noise reduction
  • Privacy: On-device toggle (default ON), cloud sync, data export, delete all
  • Notifications: Alarm style, digest reminder, weekly wrap
  • Integrations: Google Calendar, Notion, Google Tasks (Pro tier)
  • Account: Pro upgrade, subscription management, help
Upgrade UX Rules
  • Never show a paywall popup without user action
  • Pro features are visible but locked with a subtle lock icon — not hidden
  • Upgrade row appears once in settings, never as a banner or modal
  • Free tier clearly shows remaining allowance (e.g., "18/20 captures used")
Grouped layout Privacy-first defaults Non-pushy upgrade row

03 — Guidelines
Design Principles
Every design decision must pass through these five principles. If a proposed feature or UI element fails any of them, it doesn't ship.
⚡
Sub-1-second to capture
From thought to recording must be under 1 second. If any step in the flow adds latency or friction, it's cut. The bubble tap must feel instant.
🔒
Privacy visible by default
The "on-device only" toggle is ON by default. Privacy icons are visible in recording state. Users must actively choose to share data, never tricked.
👁
State is always legible
A user must be able to tell in under 0.5 seconds: is it recording or not? The color-coded bubble makes this impossible to misread.
🚫
Zero interruption design
No unsolicited popups, no forced ratings dialogs, no interstitial ads. The app earns attention — never steals it. Even upgrade prompts are passive.
✂️
If in doubt, cut it
Feature creep kills focus apps. Every element on screen must earn its place. When a screen looks "full," remove things — never add more.
📱
Thumb-first design
All primary actions reachable with right thumb. Bottom navigation. Bubble in bottom-right. Critical buttons in the bottom 60% of screen. Nothing important above the fold.

03 — Guidelines
Do / Don't
Based on mobile UI research: 88% of users abandon after bad UX. These rules prevent the most common failure modes.
✓ Do
Use 48dp minimum touch targets everywhere
Show recording state in notification bar (Android requirement)
Provide haptic feedback on bubble tap
Animate state transitions (100–200ms, ease-out)
Support one-handed use — all critical actions in thumb zone
Test on low-end devices (≥2GB RAM, Android 10)
Use system fonts as fallback if custom fonts fail to load
Provide offline-first experience for all core features
Show empty states with helpful guidance, not just blank screens
Support dark mode only (primary) + optional light mode later
✗ Don't
Never show a paywall modal without user initiating upgrade
Never use red for anything except destructive actions
Never put important actions above the fold (top 40% of screen)
Never use more than 2 font families on one screen
Never block recording with a loading state
Never play audio without user explicitly tapping play
Never show more than 1 ad per digest email (free tier)
Never require account creation before first capture
Never use a bottom sheet for settings — use a full screen
Never auto-start recording without explicit user action
